## Architecture and invariants

Three native applications share specifications, not a runtime. Android uses a ViewModel/StateFlow, DataStore for non-secret preferences and Compose; Windows uses Win32/C++20 and HKCU; macOS uses AppKit/Swift and UserDefaults. Each platform has one generator and one authoritative preference state. Android's applicationId remains `com.sl.passwordgenerator`, minSdk 26, targetSdk 36. VERSION remains authoritative for unified native releases. Canonical artwork and the PolyForm Noncommercial license are unchanged.

All implementations use platform CSPRNGs and unbiased bounded selection. The mandatory-group generation algorithm is not a claim of uniform sampling over every valid password. The strength score is a heuristic, not a measured security guarantee. No networking, ads, tracking, analytics, accounts, password persistence or cross-platform runtime was added. The app is a generator, not a password manager.

## Removed, consolidated and simplified

- Removed obsolete Lint/Qodana WebP/resource-path exclusions and a stale Detekt magic-number entry.
- Bundled upstream Apache 2.0 runtime notices/license text in Android assets; the product license remains PolyForm Noncommercial.
- Removed Type.kt and its single-use global Typography wrapper; the theme uses the standard default directly.
- Reviewed Espresso for removal, then preserved the direct declaration: it pins the Compose test engine to the checksum-verified 3.7.0 instead of selecting an older transitive version.
- Removed desktop duplicate clipboard password state and associated text reads/copies, redundant Win32 preference reread and obsolete macOS version branch.
- Consolidated compiled Android checks into one local composite action used by CI and signed candidate/release builds.
- Kept signing, package verification and listing verification separate because they have different trust boundaries and inputs.

## Dependencies, legacy and intentionally preserved code

Added one build-only, hash-pinned defusedxml parser for hardened compiled-manifest XML validation, with a DTD/entity rejection regression. It is installed in an isolated CI virtual environment and never packaged into the app. Every declared dependency was checked against production, test or build usage. There are no third-party desktop runtime dependencies. Existing Android libraries and toolchain are retained without deleting version pins needed by transitive test engines. MSVC native code analysis is enabled in the Windows build; bulk upgrades in unrelated Dependabot PRs are not folded into this refactor. Resolved dependency vulnerability results, rather than version freshness alone, govern readiness.

The legacy Android password-key deletion remains necessary for updates from 1.4.1 and earlier. Backup exclusions remain even with allowBackup=false because device transfer is platform-controlled. JavaPoet verification pin, Gradle checksum metadata, source-attachment trust exceptions, official wrapper files, immutable historical releases and explicit native platform boundaries remain. The existing generator algorithm and strength heuristic are preserved; replacing them would change the shared product contract. No working abstraction was removed solely because it has one implementation.
